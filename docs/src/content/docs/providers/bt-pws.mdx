The BeyondTrust Password Safe provider retrieves a managed account password
through the Password Safe Public API. It is read-only.

## At a glance

| | |
| --- | --- |
| Provider | `bt-pws` (0.5.0+) |
| URI | `bt-pws://HOST[?base_url=URL&system_name=NAME&api_version=VERSION]` |
| Access | Read-only |
| Authentication | API key and run-as user (with optional personal access token or interactive MFA), or OAuth client credentials |
| Availability | Monosecret 0.5.0+; included in default builds (`bt-pws` feature) |
| Default storage | A managed account named by `ref` |

## Quick start

Set either the API-key credentials or OAuth client credentials described below,
then retrieve a referenced account without printing its password:

```bash
$ monosecret run --provider beyondtrust -- your-command
```

## Setup

Create a Password Safe Public API registration and grant its identity permission
to view and request access to the managed accounts Monosecret will retrieve.

### API key and run-as user

For API-key authentication, configure the key and authorized run-as user:

```bash
$ export BTPWS_AUTH_KEY=...
$ export BTPWS_RUNAS=service-account@example.com
```

### Personal access token

To include a Password Safe personal access token in the `PS-Auth` header, also
set:

```bash
$ export BTPWS_PERSONAL_ACCESS_TOKEN=...
```

### MFA

When Password Safe responds with an HTTP 401 MFA challenge, Monosecret prompts
for the one-time password without echoing it. MFA requires an interactive
terminal and is supported with API-key authentication.

### OAuth client credentials

OAuth machine clients use a client-credentials exchange at
`POST {base_url}/auth/connect/token`, then sign in with the returned Bearer
token:

```bash
$ export BTPWS_CLIENT_ID=...
$ export BTPWS_CLIENT_SECRET=...
```

When both OAuth variables are present, OAuth takes precedence over API-key
authentication. The access token is held only for the current resolution.

## Configuration

### URI format

```text
bt-pws://HOST[:PORT][?base_url=URL&system_name=NAME&api_version=VERSION]
```

`HOST` derives `https://HOST/BeyondTrust/api/public/v3`. `base_url` overrides
that complete API base URL, which is useful when Password Safe is served at a
nonstandard path. `system_name` supplies the managed system when a secret
reference omits `field`.

`api_version` is accepted for forward-compatible configuration.

### Security rules

- Remote endpoints must use HTTPS; plain HTTP is permitted only for loopback
  hosts (`localhost`, `127.0.0.1`, `::1`).
- HTTP redirects are disabled so authorization headers and session cookies
  cannot be forwarded to another host.
- Credentials cannot be passed in URI userinfo or query parameters; configure
  them through `[providers.<alias>.credentials]` or `BTPWS_*` environment
  variables.

### URI examples

```text
bt-pws://passwordsafe.example.com
bt-pws://passwordsafe.example.com?system_name=database-server
bt-pws://passwordsafe.example.com?base_url=https%3A%2F%2Fpasswordsafe.example.com%2FBeyondTrust%2Fapi%2Fpublic%2Fv3
```

### Project configuration

```toml title="monosecret.toml"
[providers]
beyondtrust = "bt-pws://passwordsafe.example.com"

[profiles.default]
DATABASE_PASSWORD = { description = "Database password", ref = { item = "database-user", field = "database-server" }, providers = ["beyondtrust"] }
```

## Storage model

Password Safe is not a key/value store: Monosecret retrieves an existing
managed account and never creates one. In a reference, `item` is the managed
account name and `field` is the managed system name. When `field` is omitted,
the provider uses `system_name` from its URI.

Without a `ref`, Monosecret uses the conventional account name
`{project}/{profile}/{key}`. Configure `system_name` in that case; explicit
references are recommended for existing managed accounts.

The provider creates a five-minute `View` request (using the configured access
reason or `Monosecret`), retrieves the resulting credential, and always signs
out — reporting a sign-out failure rather than silently ignoring it. The
Password Safe account must be authorized to view and request access to the
referenced managed account.
